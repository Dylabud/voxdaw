* **[2026-04-30] Phase 9 — Gesture-Controlled Arpeggiator (Right Hand):** Added a `Tone.Pattern`-based arpeggiator driven entirely by right-hand gestures. Three new pure functions added to `dsp.js`: `getArpFingerStates(hand)` (rotation-robust wrist-to-tip vs wrist-to-PIP distance ratio, 1.1× threshold for noise immunity), `getWristTiltDeg(hand)` (atan2 of wrist→midMCP vector normalized to upright=0°, absolute deviation for bidirectional tilt), and `getArpSpreadDb(hand, states)` (outermost extended-tip Euclidean distance → −24 to 0 dB). `useAudioEngine` gains a dedicated `Tone.Synth` arp voice (triangle, plucky 5ms attack / 120ms decay) plus a dedicated `Tone.Volume` tapped before the shared filter so arp gain is independent of the main pinch-velocity volume. `Tone.Pattern` is created once in `startAudio`, always running on `Tone.Transport` (120 BPM), and silenced via `pat.mute` — no start/stop churn on each rAF frame. Six modes mapped to finger combinations: OFF / SIMPLE (upDown, 1-oct major) / COMPLEX (upDown, 2-oct) / CMPLX RND (randomWalk, 2-oct) / SMP RND (random, 1-oct) / OCTAVE (root+12, upDown). Rate snaps in three bands: < 20° = 4n, 20–60° = 8n, 60°+ = 16n (absolute wrist tilt from vertical). When arp is active, all four chord voices are muted via `rampTo(VOICE_MUTE)`; chord logic restores automatically on transition back to OFF. `Tone.Transport` started in `startAudio` and stopped in `stopAudio`. `arpRef` added to `hudRefs` and `TelemetryHUD` displays current mode label.
