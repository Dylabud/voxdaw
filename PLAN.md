* **[2026-05-08] Phase 38 — Fix Fluid Arp Pause (Synchronize rAF + Scheduler):** The previous fix (Phase 37 — 5% threshold) eliminated the stutter but introduced a pause: any call to `pat.interval = x` from the rAF loop triggers `_rescheduleEvents()` which resets Tone.js's countdown timer. While the hand tilts continuously, the countdown kept resetting before completing, so no note ever fired. Fix: added `fluidUpdateReadyRef = useRef(false)`. The Pattern callback sets it `true` after firing a note in fluid mode. The rAF loop only updates `pat.interval` when the flag is `true`, then immediately resets it to `false`. This guarantees exactly one `_rescheduleEvents()` call per note cycle — after the note fires and before Tone.js queues the next one — so the countdown is never interrupted mid-flight. `smoothedFluidIntervalRef` continues to lerp toward the tilt target every frame; the flag just gates when that value is pushed into the scheduler. Flag reset added to `stopAudio`.

* **[2026-05-08] Phase 37 — Fix Fluid Arp Rate Stutter:** The `[ speed snap ]` off (fluid) mode was stuttering because `arpPattern.interval = fluidTime` was assigned from inside the `Tone.Pattern` callback itself. Tone.js calls `_rescheduleEvents()` when `interval` changes — doing this from within the scheduler tick corrupts the lookahead queue (double-fires, missed beats). Fix: removed the self-assignment from the Pattern callback entirely; moved `pat.interval = smoothed` to the rAF loop (safe context, outside Tone.js's tick). Added a 5% relative threshold (`Math.abs(smoothed - prevNum) / prevNum > 0.05`) so the scheduler is only updated 10–20 times/second during a sweep instead of 60fps. `appliedArpRateRef` is repurposed to hold the last-applied float in fluid mode (was hardcoded `null`); the snap-mode delta check (`rate !== appliedArpRateRef.current`) still works correctly since string/number comparison is always `true` on mode transition.
